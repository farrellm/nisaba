# Frontend

The Vite dev server proxies all `/api/*` requests to `http://localhost:8080`, so the browser never makes a cross-origin request during development.

Routing uses `react-router-dom` (routes in `src/App.tsx`, providers in `src/main.tsx`). Call the API via `src/api/client.ts` (`api.get/post/put`, sends the session cookie) rather than raw `fetch`. Frontend API types are in `src/api/types.ts` (`Document`, `DocumentDetail`, `Block`, `Response`, `Mode`, `LLMModel`); treat any array from the API as possibly `null` and guard with `?? []`. Current user comes from `useAuth()` (`src/auth/AuthContext.tsx`); wrap protected routes in `RequireAuth`, which redirects to `/login`. The document view (`pages/DocumentPage.tsx`) renders blocks via `components/BlockCard.tsx`, adds them via `components/AddBlockDialog.tsx`, and picks the model via the fixed lower-left `components/ModelSelector.tsx` (auto-saves through `PUT /api/documents/{id}`). There is no shared layout wrapper — each page renders its own chrome: `components/Masthead.tsx` for the standard nav, `components/AuthLayout.tsx` (or simply omitting the masthead) for chrome-free pages, and the tab title via the `usePageTitle` hook. Render markdown/LLM output through the reusable `components/Markdown.tsx` (react-markdown + remark-gfm), which carries the editorial styling — don't reach for another markdown lib. It renders no raw HTML (no `rehype-raw`), so XML/HTML tags in model output are dropped unless escaped (`<` → `\<` makes them render as literal text). Rendering and editing are separate stacks: `Markdown.tsx` is read-only output, while `components/AttributeEditorDialog.tsx` is a full-screen WYSIWYG **editor** for one document attribute, built on Milkdown Crepe (`@milkdown/crepe`) and lazy-loaded from `DocumentAttributes.tsx`. It creates the editor from a **callback ref**, not an effect — MUI's Dialog portals its content in after mount effects run, so a `rootRef` would still be null and the editor would come up blank. Per-attribute icon links (in `BlockCard`/`components/DocumentAttributes.tsx`) open chrome-free, full-page standalone views in a new tab (`pages/AttributePage.tsx`, `pages/BlockAttributeDiffPage.tsx`, routed under `/documents/:id/...`) that re-fetch by id rather than taking props — mirror this for new attribute viewers. `AttributePage` is **deliberately shareable**: it and its route sit outside `RequireAuth` and read `GET /api/public/documents/{id}/attributes/{key}` — the only route outside the backend's `RequireUser` group. Access is open by guessable sequential id by design; it returns an empty value (never 404) so it can't be used to probe which documents exist. Don't add an auth check there, and don't extend it to return anything beyond one attribute value plus the title. Word-level diffing lives in `lib/wordDiff.ts` (algorithm documented in `lib/wordDiff.md`). Labels UI: `pages/LabelsPage.tsx`, `components/EditLabelsDialog.tsx`, and `components/AuthorField.tsx`.

The tsconfig targets ES2020 (`lib: ES2020`), so newer stdlib like `String.replaceAll`/`Array.at` isn't typed — use ES2020-compatible equivalents. There is no frontend test runner — verify pure-logic utilities (e.g. `src/lib/`) with a quick `node -e` port of the function.

The frontend's `parseResponseSegments` (`src/lib/responseSegments.ts`) mirrors the backend's `internal/tagparse` byte-scan for ordered rendering and must be kept in sync.
