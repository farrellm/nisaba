# Backend

**The LLM call is provider-agnostic.** `blockrun.Service` (`internal/blockrun`) orchestrates a run — `Prepare` persists the caller's edits and renders the prompt + system prompt (`mode.Templates.SystemPrompt`, a per-user-overridable mustache template), `Execute`/`ExecuteStream` make the model call (detached from the client connection, bounded at 15m) and save/reparse the response; the HTTP handlers in `internal/handler/block.go` map its step-typed errors onto responses. It calls `llm.Generate(ctx, model, system, prompt, tools)` (`internal/llm`), a thin wrapper over the [GoAI SDK](https://github.com/zendev-sh/goai) that routes each model through the provider named in its `Model.Provider` — its own vendor (Anthropic/OpenAI/Google) or the OpenRouter aggregator — GoAI reads that provider's key from the environment (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`/`GOOGLE_GENERATIVE_AI_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY`). The service passes the mode's `Tools`; when non-empty, `Generate` attaches each tool and runs GoAI's agentic loop (`WithMaxSteps`, bounded by `maxToolIterations`) so the model can invoke tools and have results fed back, otherwise it does a single generation. Each document picks a model from a single **fixed, cross-provider list** (`llm.Models()`, served at `GET /api/models`); `Run` 400s if no model is selected. Keep all vendor-specific code behind `internal/llm` — never import a single-vendor SDK directly. `llm.Tool` is an alias for GoAI's tool type; build one with `goai.NewTool` (schema auto-generated from a typed input struct's `json`/`jsonschema` tags — no hand-written param schema). `internal/llm/names.go` ships a ready-made `llm.GenerateNameTool` (`generate_name`, returns a non-blocklisted character name) as a worked example — currently attached to the `brainstorm-tools-*` modes. `internal/llm/labels.go` is a second worked example: `llm.SuggestLabels(ctx, story)` hard-codes a model, renders the embedded `templates/suggest-labels.mustache`, and parses `<label>` tags out of the reply (templates that drive a hard-coded-model helper live under `internal/llm/templates/`, since `go:embed` can't reach a parent dir). The same file's `llm.SelectLabels(ctx, story, available)` renders `templates/available-labels.mustache` and filters the reply down to the supplied label set (picking relevant ones from an existing pool rather than inventing new labels).

Internal packages:

- `internal/config` — reads `ADDR`, `DATABASE_URL`, `CORS_ORIGINS`, `SESSION_SECRET`, `SESSION_SECURE`, `MODE_TEMPLATES_DIR` from env with local dev defaults. Reddit integration reads `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET` for reading and `REDDIT_USERNAME`/`REDDIT_PASSWORD` for submitting (handlers 503 when the relevant pair is unset)
- `internal/auth` — cookie-session helper (gorilla/sessions, signed, HttpOnly). `SESSION_SECRET` signs the cookie (dev default; prod must override); `SESSION_SECURE=true` sets the Secure flag for HTTPS. Also carries the request-scoped user id: the `handler.RequireUser` middleware injects it and handlers read it via `auth.UserIDFrom(r.Context())`
- `internal/db` — opens a `pgxpool.Pool` and pings on startup to fail fast
- `internal/handler` — `http.HandlerFunc` closures; the full route tree lives in `routes.go` (`handler.Routes(handler.Deps{...})`, wired from main.go), with every authenticated route inside the `RequireUser` middleware group (401 + user id into context), so handlers don't check sessions themselves. Handlers accept small consumer-side interfaces declared next to them, which `*store.Store` satisfies structurally — fakes make handlers unit-testable (see `document_test.go`); only the `/api/auth` handlers take `*auth.Sessions`. Shared JSON/error helpers live in `respond.go`. Non-obvious behaviors: `GET /api/documents/search?q=` is Postgres FTS over the `story` attribute (`to_tsvector('english',value) @@ websearch_to_tsquery`, ranked by `ts_rank`, backed by a partial GIN index in migration `000007`; archived docs included, empty `q` returns `[]`). `PUT /api/documents/{id}` body fields (`selectedModel`, `attributes`, `isArchived`, `labels`) are optional pointers applied only when present — attributes merge via `MergeDocumentAttributes` (absent keys survive), labels go through `SetDocumentLabels`, which reconciles the join by name and reuses existing labels. Labels are user-global tags; a label is deleted once it's attached to no document (orphan cleanup in `SetDocumentLabels` and `DeleteDocument`, which is therefore transactional and takes `userID`). `POST /api/documents/{id}/suggest-labels` invents new names via `llm.SuggestLabels`, `.../recommend-labels` picks from the caller's existing labels via `llm.SelectLabels` — both read-only, returning names the caller applies itself via `PUT`; both 400 when the document has no `story` yet. Shared helpers `ownedDocument`/`findBlock` enforce ownership. **There is no registration endpoint** — accounts are created only by the server binary's `-create-user` flag (with `-list-users`/`-delete-user` alongside it; see `cmd/server/users.go`), so `/api/auth` is login/logout/me only and the frontend has no signup page. Conventions: resources owned by another user return **404, not 403** (don't leak existence); list endpoints guard `nil` slices so the JSON body is `[]`, never `null`
- `internal/reddit` + `internal/handler/reddit.go` — optional Reddit import feature. `reddit.Client` is the OAuth client (app-only `client_credentials` token, cached and refreshed; anonymous JSON access is blocked; Reddit requires a descriptive `User-Agent`), exposing `NewestPosts`, `FetchPost` (with the `postPath` SSRF guards and share-link resolution), and `SubmitSelfPost`; it returns typed errors (`ErrNotFound`, `ErrRateLimited`, `StatusError`, `SubmitError`, …) that the thin handlers map onto HTTP via `writeRedditError`. `GET /api/reddit/posts` lists newest posts from the user's configured subreddit; `GET /api/reddit/post?url=` fetches one post. Both 503 when `REDDIT_CLIENT_ID`/`_SECRET` are unset. Read-only: the app-only token has no user identity and **cannot submit**. Submitting is separate — `POST /api/documents/{id}/reddit-submit` (`SubmitRedditPost`, nested so it own-checks via `ownedDocument`) publishes a self post with a `password`-grant token (the script-app account `REDDIT_USERNAME`/`REDDIT_PASSWORD`, 503 when unset), saves the returned permalink to the `document_posts` child table, and returns the refreshed document. `PUT /api/auth/me` (`UpdateMe` in `auth.go`) is a partial update (optional-pointer body) of per-user settings: `subreddit` (validated, defaults to `WritingPrompts`; migration `000004`) and `streamingEnabled` (migration `000006`; toggles live-streamed responses, surfaced as a Switch in `AccountMenu` and consumed by `BlockCard`/`api.postStream` over an NDJSON `POST .../run/stream`). Frontend: `SettingsPage`, `RedditPostsPage`, `RedditPromptDialog`/`RedditUrlDialog`, `RedditSubmitDialog` (document ⋮ menu; seeds title from the original prompt and body from the `story` attribute)
- `internal/handler/legacy.go` — the read-only **"Anansi"** browser over the legacy `reflex.db` SQLite file (an older version of this app; schema maps onto the current models: `doc`→Document, `block`→Block (carries its own `model`, surfaced on each `Response.Model`), `blockresponse`→Response, `doctag`/`blocktag`→attributes, `label`→labels). `GET /api/anansi/documents` (list, newest first, archived included) and `GET /api/anansi/documents/{id}` (full aggregate) — require a logged-in session but are **not** user-scoped (legacy data is shared and read-only). One handler set (`ListLegacyDocuments`/`GetLegacyDocument`/`ImportLegacyDocument` over the `LegacySource` interface) serves both this and the Charlotte tree below. `POST /api/{anansi,charlotte}/documents/{id}/import` copies a legacy document into the caller's own documents (`handler/import.go`), translating legacy block-mode names onto the current registry via `legacyModeMap` and falling back to `generic` for anything unrecognized, so an imported block stays editable and runnable. Backed by `store.ReflexStore` (`store/reflex.go`) over `*sql.DB` opened via `db.OpenSQLite` (`mode=ro&immutable=1`, driver `modernc.org/sqlite`, pure-Go); the SQLite handle is opened in `main.go` from `cfg.ReflexDBPath` (env `REFLEX_DB_PATH`, default `../reflex.db`, gitignored). The driver returns `DATETIME` columns as `time.Time` directly. Frontend: landing-page card → `AnansiPage` (`/anansi`, reuses `DocumentList`/`DocumentRow` via their optional `basePath`/`showArchived` props) → read-only `AnansiDocumentPage` (`/anansi/:id`), a thin wrapper over the shared `components/ReadOnlyDocumentPage` (also used by Charlotte). `ReadOnlyDocumentPage` deliberately mirrors the live document-page structure read-only — the structured/raw response rendering and collapsible key/value fields are shared with `BlockCard`/`DocumentAttributes` via `components/ResponseView.tsx` and `components/CollapsibleValueField.tsx` (no manual sync needed), minus all edit/run/save/delete affordances
- The parallel read-only **"Charlotte"** browser (same `legacy.go` handlers) works over the external `charlotte-cli` executable (an older file-based version of this app). `GET /api/charlotte/documents` / `/{id}`, logged-in but not user-scoped. Backed by `store.CharlotteStore` (`store/charlotte.go`), which shells out: `charlotte-cli --list` enumerates document names (used as titles), `charlotte-cli --doc <name>` dumps one as JSON (`docTitle`/`docUrl`/`docTags`/`docBlocks[]` → the same `model.Document` aggregate; `parseCharlotteDoc` does the pure mapping). Docs are identified by name, not id — the store assigns stable ids by indexing the **sorted** `--list` output and resolves id→name again on fetch. A non-zero CLI exit (the legacy tool fails to parse a doc) surfaces as an error. Executable from `cfg.CharlotteCLI` (env `CHARLOTTE_CLI`, default `charlotte-cli` on `PATH`); unlike Anansi's SQLite, a missing CLI does **not** fail startup. Frontend: landing-page card → `CharlottePage` (`/charlotte`, `defaultSort="alpha"` + `hideTime` since the CLI exposes only names) → `CharlotteDocumentPage` (`/charlotte/:id`, wraps `ReadOnlyDocumentPage`)
- `internal/mode` — the fixed mode registry: `Mode{Name, Label, Keys, Output, Template, Tools, Renames}`, with mustache templates embedded from `templates/*.mustache` via `go:embed`. `All()` / `Get(name)`. The `Template` and `Tools` fields are `json:"-"` so they stay server-side. Add a mode by adding an entry plus its template file; attach tools by setting `Tools: []llm.Tool{...}` (see the LLM paragraph above). **Per-user template overrides**: `mode.Templates` (constructed once in main.go via `mode.NewTemplates(cfg.ModeTemplatesDir)`; env `MODE_TEMPLATES_DIR`, default `internal/mode/templates`) resolves runtime overrides — `Templates.ModeTemplate(username, mode)` (used by `blockrun.Service`) reads `<baseDir>-<username>/<mode>.mustache` (sibling of the default dir) when present, else falls back per-file to the embedded default. The shared system prompt works the same way via `Templates.SystemPrompt(username, provider)` (per-user override file `<baseDir>-<username>/system.mustache`, default `templates/system.mustache`), but first prefers a per-provider override `system-<provider>.mustache` (provider = the selected model's `llm.ProviderFor(id)`, e.g. `anthropic`/`openai`) when present, so a user can tune the system prompt per provider; all go through the internal `lookupOverride` helper. Usernames are validated (`[A-Za-z0-9_-]` only) to prevent path traversal; the override dirs (`templates-*/`) are git-ignored
- Response processing: `internal/tagparse` (`tagparse.Parse`) byte-scans free-form responses (not `encoding/xml`) for top-level tags, counting same-name nesting depth and degrading gracefully on malformed input (an unclosed final tag is auto-closed at end of string). The frontend's `parseResponseSegments` (`frontend/src/lib/responseSegments.ts`) mirrors this scan for ordered rendering and must be kept in sync. `blockrun.Service.Reparse` merges the parsed tags (applying the mode's `Renames`, plus the `output` key when set) via `MergeDocumentAttributes`. Covered by `tagparse_test.go` and `blockrun_test.go` (run with `make backend-test`; see also `internal/llm/names_test.go`)
- `internal/blockrun` — the block-run service (see the LLM paragraph above): `Prepare`/`Execute`/`ExecuteStream`/`Reparse` over small `Store` and `Generator` interfaces, so `blockrun_test.go` covers the whole pipeline with fakes. `blockrun.MergedAttrs` builds a block's attribute map for a mode's fixed key set (also used by the update/copy handlers). NDJSON transport (headers, keepalive pings, event framing) stays in `handler/block.go`
- `internal/llm` — provider-agnostic LLM wrapper over the [GoAI SDK](https://github.com/zendev-sh/goai). Holds the fixed cross-provider model list (`Models()` / `Valid(id)`) and `Generate(ctx, model, system, prompt, tools)` (the system prompt is supplied by the caller — see `mode.Templates.SystemPrompt`). Each `Model`'s `Provider` field selects the GoAI provider client (`clientFor` routes to `anthropic`/`openai`/`google`/`openrouter`/`deepseek` `.Chat`). A `Model` carries **two distinct names**: `ID` is the provider-native one that client expects (a vendor-native id, or an OpenRouter slug like `z-ai/glm-5.2`), while `Key` is the app's identity for it — what's stored in `documents.selected_model`/`responses.model`, served as `id` on the wire, and taken by `lookup`/`Valid`/`ProviderFor`. `Key` defaults to `ID` at init, so most entries declare `ID` alone; set it explicitly only for **variants** — several entries may share one `ID` while differing in `Key`, `Label` and `ProviderOptions` (e.g. `z-ai/glm-5.2:max` vs `z-ai/glm-5.2`, same upstream model at a different reasoning effort). Keys must be unique; `init` panics otherwise. Aliases GoAI's `Tool` type so modes attach tools without importing the vendor library. `ToolCaching: true` turns on ephemeral prompt caching for a model's tool-bearing calls (`goai.WithPromptCaching` for the tools+system prefix, plus a part-level `CacheControl` marker on the user prompt, which is why that path builds the message with `goai.WithMessages` instead of `WithPrompt`) — Anthropic-only, since GoAI warns on stderr for other providers; a raw `cache_control` provider option does **not** work, the Anthropic provider passes unhandled keys through as top-level request-body fields. The only place vendor/provider code lives; add a model by appending to the list with its native ID and provider. `Hidden: true` drops an entry from `Models()` (so it leaves `GET /api/models` and the UI selector) while `lookup`/`Valid`/`ProviderFor` still resolve it, so keys already stored in documents/responses keep working — `claude-haiku-4-5` is currently hidden this way. End-to-end verification runs should always use `claude-haiku-4-5` (cheapest/fastest) unless the change under test is model-specific. `GenerateStream(..., onDelta)` is the streaming sibling of `Generate`: it consumes GoAI's raw chunk stream (`ts.Stream()`) so reasoning streams live, frames it like `combineSteps` (`<thinking>`/`<toolname>` tags), and returns the same final value via `combineSteps(ts.Result())`. GoAI gotchas (v0.9.4): `ts.TextStream()` forwards only text (no reasoning); `WithOnStepFinish` fires at step *end* (`StepResult.ToolResults` is always empty there); `ChunkToolResult` is never emitted — tool results land only in the final result; the agentic tool loop runs automatically however chunks are consumed
- `internal/model` — plain domain structs mirroring the DB schema (no data-access logic); JSON-tagged, aggregate-shaped for API bodies
- `internal/store` — `Store` wraps the pool with raw-SQL CRUD methods over the models; returns `store.ErrNotFound` for missing rows and `store.ErrDuplicate` for uniqueness violations (detected in the store via `pgerrcode`, so `pgconn` never leaks into handlers). Every exported method annotates escaping driver errors with its operation name (`defer wrap(&err, "...")`; sentinels pass through unwrapped). `GetDocument` loads the full aggregate (blocks → attributes/responses) with batched queries
- **Empty Go slices marshal to JSON `null`, not `[]`** — embedded aggregate slices (`Document.Blocks`/`Labels`, `Block.Responses`) must be defaulted to an empty slice in the store, or the frontend crashes on `.length`/`.map`. `GetDocument`/`GetBlock` guard `Blocks`/`Responses`; `Labels` is not yet guarded, so guard slice access with `?? []` on the frontend too

Handlers are plain `http.HandlerFunc` (no framework-specific types). CORS is handled by `rs/cors` middleware — it's unused during local dev (covered by the Vite proxy) but activates in production.

## Adding a New API Endpoint

1. Add a handler function in `internal/handler/` returning `http.HandlerFunc`; take the store as a small consumer-side interface (extend the file's existing one, or declare what you need)
2. For user-scoped data, register the route inside the `RequireUser` group and read the caller via `auth.UserIDFrom(r.Context())` (defensive 401 if absent) — see `document.go`
3. For resources nested under a document (`/documents/{id}/...`), reuse the `ownedDocument`/`findBlock` helpers in `block.go` and register inside the nested `r.Route("/{id}", ...)` group rather than re-checking ownership
4. Register the route in `internal/handler/routes.go` inside the `/api` route tree
5. Call it from `frontend/src/` using a relative `/api/...` path
